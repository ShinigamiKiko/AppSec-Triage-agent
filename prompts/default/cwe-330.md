## CWE-330 family — insufficiently random values

The decisive question is **what the random value is used for**, not which API produced it. A weak PRNG is only a vulnerability in a security context.

### Security context (→ `confirmed`)

The value becomes, or seeds: session ID, CSRF token, password-reset token, API key, nonce/IV, salt, OTP, invite code, cryptographic key material, any "unguessable" URL.

### Non-security context (→ `false_positive`)

Jitter/backoff on retries, shuffling test data, sampling for telemetry, picking a shard or replica, generating placeholder UI content, animation timing, load-test payloads, cache-busting suffixes.

### API rules

| API | Direction |
|---|---|
| `java.util.Random`, `Math.random()`, C `rand()`, Python `random.*`, Go `math/rand` | Weak — verdict depends on the use |
| `SecureRandom`, `crypto.randomBytes`, `secrets.*`, `os.urandom`, Go `crypto/rand` | `false_positive` — the analyzer misfired |
| `SecureRandom` with a **fixed seed** (`setSeed(constant)`) | `confirmed` — seeding destroys the guarantee |
| `new Random(System.currentTimeMillis())` used for a token | `confirmed` — time-seeded and guessable |
| `UUID.randomUUID()` | `false_positive` for identifiers; `unknown` if used as a bearer secret |

### When the use is not visible

If the evidence shows the generation site but the consuming sink is not reported and the variable name gives no hint → `unknown`, `INSUFFICIENT_CONTEXT`, and put `"consumer of the random value not visible"` in `missing_information`. Do not guess a security context from the file name alone.
